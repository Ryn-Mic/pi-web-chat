# pi-web-chat Agent Guide

## Project Overview

- This package provides a mobile-friendly Web UI for the pi coding agent.
- Runtime stack: Node.js 20+, pi SDK, HTTP/WebSocket server, React 19, TanStack Router/Query, Tailwind CSS, Vite, and PWA assets.
- Production artifacts are `dist/index.js` and `dist/public/`. They are generated by `npm run build`; never edit them directly.

## Architecture Map

- `extensions/pi-web-chat.ts`: pi package entry; implements `pi --web` and `/web`, starts/stops the managed daemon, and owns daemon state files.
- `server/index.ts`: HTTP API, WebSocket transport, authentication, session runtimes, static files, and graceful shutdown.
- `server/session-*.ts`, `server/serialize.ts`: JSONL session indexing, active-branch pagination/sync, and UI serialization.
- `server/files.ts`, `server/file-content.ts`, `server/git.ts`: cwd-scoped filesystem, preview, and Git APIs.
- `shared/protocol.ts`, `shared/snapshot.ts`: authoritative server/client contracts and snapshot delta semantics.
- `src/lib/chat.ts`: client connection, reconnect/replay, per-session state, history paging, and command transport.
- `src/components/`: UI; `ChatPage.tsx` composes the session, message, composer, files, and Git surfaces.
- `src/main.tsx`: auth gate and `/` / `/s/:sessionId` routing.
- `tests/`: Node tests mirror source modules; `tests/e2e/` contains Playwright coverage.

## Non-Negotiable Invariants

- Keep server and client protocol changes atomic: update `shared/protocol.ts`, producers, consumers, reconnect/full-snapshot paths, and tests together.
- Sessions are independent. Preserve each session's cwd, runtime, socket generation, history cursor, optimistic state, and preview workspace; never fall back to the Web server process cwd for session tools.
- Session JSONL is branched and can be large. Operate on the active branch, retain tool-call/result pairing, page history, and avoid loading or reparsing the full transcript on routine UI actions.
- Treat `isStreaming` as a hint, not proof that an agent is stuck. Diagnose with session API state, JSONL events/mtime, process state, and upstream errors before stopping anything.
- Every API and WebSocket route must retain authentication and cwd/path authorization. Never print, commit, or return access tokens, TOTP secrets, API keys, or session credentials.
- Only a daemon started by `pi --web` may update `~/.pi/web-chat/pi-web-chat.{pid,port,host}`. Debug servers must not mutate managed daemon state.
- Preserve PWA/file-preview isolation, cache behavior, and lazy-loading boundaries. Build changes must still pass the checks in `scripts/build.mjs`.

## Change Discipline

- Start with `git status --short` and scoped diffs. The worktree may contain user changes: preserve them and do not reset, clean, stash, or stage unrelated files.
- Use existing modules and tests before adding parallel abstractions. Keep fixes narrow and add a regression test for every reproducible bug.
- Do not commit, publish, install, stop sessions, delete state, or change remote systems unless the user explicitly authorizes that action.
- Do not edit generated output, vendored assets, session JSONL, or files under `~/.pi` as a substitute for fixing source code.

## Versioning and Release Notes

- Every requirement, optimization, or bug-fix delivery increments the patch version exactly once; never reuse a version for different work.
- Keep the version synchronized in `package.json` and both root/package entries in `package-lock.json`.
- Add concise user-facing entries under the same version in `release-notes.json`.
- When continuing unfinished local work, preserve its intent and include the complete delivered scope in the new version notes.

## Verification Matrix

- TypeScript changed: `npm run typecheck`.
- Source behavior changed: run focused tests, then `npm test` before handoff.
- UI behavior changed: verify the real browser flow, including reconnect/session switching and long-session behavior when relevant; report any untested device-specific boundary.
- Build/server/package changed: `npm run build` and `git diff --check`.
- Package/release changed: also run `npm run pack:check` and `npm pack --dry-run`.
- Never describe unit tests as browser, multi-session, mobile-device, or production acceptance.

## Runtime and Port Safety

- Port `3141` is the protected production Web Chat service. Restart it only with `pi --web restart`, then verify:
  - `pi --web status` reports `127.0.0.1:3141`.
  - `curl -fsS http://127.0.0.1:3141/api/health` returns HTTP 200 and the intended version.
  - `lsof -nP -iTCP:3141 -sTCP:LISTEN` shows the managed server.
- Use another port for debugging, for example `PORT=3242 npm run dev:server`; point Vite at it with `PI_WEB_DEV_PORT=3242 npm run dev:web`.
- Do not run the default `npm run dev` while production 3141 is active, because its server defaults to 3141.
- A debug process may be stopped only by its known PID/session. Afterward confirm the debug port is free and production 3141 is still healthy.
- Before local production handoff: `npm run build`, optionally refresh the authorized local install with `pi update /Users/ryn/Documents/tmp/pi-web-chat --approve --force`, then use `pi --web restart`.

## Definition of Done

- Requested behavior is implemented without unrelated changes.
- Version files and release notes agree.
- Required tests, typecheck, build, diff check, and runtime/browser checks pass in proportion to the change.
- No debug listener or stale managed state remains; production stays healthy on 3141 if it was restarted.
- Handoff states what changed, what was verified, current runtime/port, and whether changes are committed.
