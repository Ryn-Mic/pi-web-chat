# 模型管理弹窗设计规格

## 目标

将模型管理从“连续表单堆叠”优化为易扫描的编辑工作台：用户能快速区分提供方、模型和高级能力，同时在浅色/深色主题、窄屏和保存异常状态下保持清晰。

## 设计决策

- 保留现有 `Dialog`、`useCustomModels`、`saveCustomModels`、草稿状态和错误处理，不改变 API 或配置数据结构。
- 弹窗继续使用项目现有的 `canvas/card/line/ink/muted/faint/accent` token，不引入新颜色体系。
- 标题区增加模型图标、标题、配置文件路径和关闭按钮；主体滚动，底部操作栏固定。
- 提供方使用带轻微底色的分组卡片，卡片头部突出提供方标识、API 类型和删除操作；连接字段使用响应式两列布局。
- 模型使用嵌套子卡片：第一行放模型序号、ID、显示名和删除操作，第二行放上下文窗口、最大 token、推理和图片输入能力；思考等级在推理开启时以可选胶囊展示。
- 添加提供方和添加模型使用带虚线/轻量边框的次级操作，主保存按钮保持 accent 实心样式。
- 底部状态文本继续承载保存成功、服务端 warning 和异常；保存中按钮禁用，避免重复提交。
- 所有图标按钮保留 `aria-label`/`title`，输入控件继续使用原有 label 文案，保证视觉简化不牺牲可访问性。

## 组件边界

- `ModelsDialog` 负责弹窗容器、标题、滚动区域、空态和底部操作栏。
- `ProviderCard` 负责提供方层级、连接字段和模型列表容器。
- `ModelRow` 负责单个模型的基础字段、能力开关和思考等级。
- 新增的本地小图标组件仅用于视觉表达，不承载数据或业务逻辑。

## 响应式行为

- 桌面端弹窗宽度约 52rem，最大高度约 88vh。
- 小屏端主体保持单列；提供方字段和模型字段在 `sm` 以下自动堆叠，按钮与删除操作保持可点击尺寸。
- 长路径、模型 ID 和 key 使用截断或可换行策略，不能撑破弹窗；配置路径保留完整 `title`。
- 主体独立滚动，标题和底部操作栏不随内容滚动。

## 验证

- `npm run typecheck`：确认 JSX、i18n 和协议类型无误。
- `npm run build`：确认 Tailwind 类和生产打包正常。
- `git diff --check`：确认无空白错误。
- 静态检查关键类名：弹窗为固定头尾结构、模型/提供方层级清楚、移动端存在 `sm` 响应式断点。
