# Agent Note: 用 content-visibility 跳过长会话里离屏的助手回复

Status: rejected — 长会话中会让远端提问的跳转失效，实测不达标

## Problem

长会话里每个已结束轮次都完整挂载：助手回复（含 Shiki 高亮的代码块）、工具卡片、思考块。折叠过程块只解决了工具卡片（`<details>` 关闭后浏览器不再布局其内容），但每个轮次的最终回答始终在过程块之外，因此 150 轮会话的滚动仍然要处理上百个 Markdown 子树。目标是让离屏回复跳过布局与绘制，同时不卸载内容——卸载会丢掉展开态、代码块高亮结果和内部滚动位置。

## Proposal

给助手回复容器加一个 `.offscreen-skip` 工具类：

```css
.offscreen-skip {
  content-visibility: auto;
  contain-intrinsic-size: auto 240px;
}
```

`auto` 关键字让浏览器复用已渲染过的尺寸，理论上只有从未渲染过的内容才使用 240px 占位。类只加在助手回复上，绝不加在用户气泡或刻度判定覆盖的其他节点上。

## Alternatives considered

- **整轮包裹一层容器再套 `content-visibility`** — 否决：轮次目前以 Fragment 形式渲染，它的兄弟节点（提问、过程块、回答）之间的间距由外层 `gap` 决定；加包裹层会改变内部垂直节奏，属于顺带的视觉回归。
- **用 `content-visibility: hidden` + 手动测量并缓存尺寸** — 否决：需要自行维护每个轮次的高度与失效时机，等价于手写虚拟化，复杂度和风险都远高于收益。
- **直接在刻度判定里忽略估算尺寸** — 否决：判定读的正是 `getBoundingClientRect()`，而 `content-visibility` 影响的是布局本身（文档总高度、元素位置），不是判定能局部补偿的。

## Acceptance criteria

- 60/150 轮会话中，从全量大纲跳转到早期提问后，目标提问顶部仍停在视口顶边（容差 24px）且高亮切回该提问；
- 会话初始贴底与滚回底部时高亮都是最新提问；
- 滚动过程中不出现明显的跳位。

## Risks

- 占位尺寸与真实高度不一致会让文档总高度和元素位置在渲染前后变化，威胁“跳转到第 N 问必须落在第 N 问”这条刚修好的契约；
- 与刻度的几何判定强耦合：判定依赖用户气泡与文档的真实布局。

## 实测结论（否决依据）

同一份 60 轮会话、同一台机器，仅切换 `.offscreen-skip`（用注入样式覆盖为 `content-visibility: visible` 作为对照）：

| 指标 | 开启 | 关闭 |
| --- | --- | --- |
| 文档 scrollHeight | 21755px | 12399px |
| 从底部点击“问题 #5”后 scrollTop | 21277 → 21105（几乎没动） | 11921 → 826（正确落位） |
| 高亮刻度 | 60（错，仍在底部） | 5（正确） |
| 回到结尾 | — | 11921，高亮 60（正确） |

即真实回复高度约 65px，而 240px 占位把文档撑高 75%，远端 `scrollIntoView({ block: "start" })` 在估算布局下不再可靠，跳转直接失效。用 `contain-intrinsic-size` 调小占位只能减轻，无法消除“从未渲染过的内容高度未知”这一根本问题。

这条否决保留的目的：任何“离屏跳过渲染/估算尺寸”的方案都必须先通过长会话跳转验证，不能因为滚动更顺就采信。可接受的替代方向是把长会话的跳转改为基于索引的显式 `scrollTop` 计算（不依赖浏览器的 `scrollIntoView`），或先做真正的虚拟化并同时接管刻度测量——两者都属于独立交付，未在本轮实施。
