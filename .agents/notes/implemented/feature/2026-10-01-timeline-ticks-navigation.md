# Agent Note: 右侧悬浮刻度状提问导航与节点跳转（Timeline Ticks）

Status: implemented

## Problem

在 v0.1.139 中彻底移除右下角常驻外挂式翻页胶囊后，消息区恢复了纯粹干净的对话阅读流，但用户在长对话中缺少了快速感知历史提问结构、跨节点快速跳转与回溯消息的交互入口。传统的目录或外挂药丸存在以下痛点：

1. **常驻外挂遮挡内容**：固定在右下角的大体积胶囊容易遮挡文字与滚底按钮，视觉上如同附着在网页上的外挂插件；
2. **长列表铺满屏幕**：当对话达到几十轮时，若简单按消息数量渲染一长条滚动条或垂直索引，会从头到尾铺满屏幕右侧，极其混乱；
3. **缺少瞬时概览与触后收拢机制**：用户通常只需要扫一眼当前处于第几问，并在需要时快速切换，不需要大面积弹窗长期占据视野。

## Decision

设计并落地右侧悬浮刻度状时间轴（Timeline Ticks / MessageTimelineTicks）：

1. **悬浮微型刻度条（Timeline Ticks）**：
   - 整体垂直居中悬浮于会话区域右侧边缘（`absolute right-1 sm:right-2.5 top-1/2 -translate-y-1/2`），高度紧凑（约 70px），宽度仅 20px，极度低调克制；
   - 每根刻度线对应一条用户提问（`user message`）；
   - **加粗变长指示当前位置**：当前视口所在的消息节点刻度加粗变长（宽 20px、高 3.5px、陶土橙 `bg-accent`），其他刻度轻巧纤细（宽 10px、高 2px、半透明微线），伴随滚动实时动态切换；
   - **最多显示 7 个刻度线，动态居中滑动窗口**：通过 `computeVisibleTicks` 算法，在总提问数超过 7 条时，以当前浏览的节点为中心动态滑动窗口，严格限制可见刻度恒为 7 个，确保无论多长的历史对话也绝不铺满右侧屏幕。
2. **轻触展开、按住滑动（Scrubbing）滚动与 2 秒无操作自动收拢**：
   - **按住滑动即时滚动（Slide to Scroll）**：支持在刻度条上直接上下拖动滑动（结合 PointerCapture 与 touch-none），根据手指 Y 坐标距离实时计算最贴合刻度，页面直接以最高响应速度（behavior: auto）平滑定位，并在手指左侧跟随显示带有 `#序号` 与文字摘要的微型实时预览气泡；
   - 默认状态仅展示纯净细微的刻度线；
   - 第一次点击（轻触）刻度条时，向左平滑滑出一个紧凑的消息卡片浮层，展示对应刻度节点的文字摘要与序号；
   - 用户可直接点击任意消息节点进行平滑滚动跳转与目标气泡闪烁高亮（`anchor-flash`）；
   - 展开态内置 2000ms 倒计时定时器：用户在面板内触摸或鼠标移动时自动顺延；若 2 秒内无任何操作，自动平滑收拢回右侧刻度条，彻底消除关闭负担；
   - **精准的当前节点判定**：修复了原先写死第一条消息的默认判定缺陷。当前节点始终是“视口顶边基准”的唯一结论：在视口触底时权威锁定最新提问；否则取已滚过视口顶边（含 `scroll-mt-4` 留白容差 `VIEWPORT_ANCHOR_TOLERANCE_PX = 24`）的最后一条提问，未滚过任何提问时回落至已加载区首条。跳转与判定共用这一条基准线，因此“点了哪一条就一定高亮哪一条”。
   - **刻度、面板与高亮统一使用全局序号**：已加载 transcript 常是整段会话的后缀，本地下标只有 1..N。刻度序号、展开卡片标题与高亮一律由 `firstLoadedUserOrdinal(totalUserCount, loadedUserCount)` 换算为全局序号，跳转反查也统一走 `messageIndexForUserOrdinal`，确保“第 45 问”永远指向服务端 anchor 索引里的第 45 问，而不是当前页的第 6 问。
3. **平滑跨页拉取与兜底**：
   - 结合 `chatClient.loadHistoryThroughUserMessage`，跳转至尚未加载到内存的历史消息时，显示微型 loading 并按需拉取补全后无缝滚动定位；
   - 在展开面板底部提供“全量大纲”入口，支持长达数百条会话下的全局检索。

## 当前节点基准线（viewport anchor）

`viewportUserOrdinal(offsets, tolerance)` 是唯一的判定函数：按文档顺序取“top 边已到达视口顶边”的最后一条提问，`null` 表示尚无提问滚过顶边。规则细节：

- **跳转与判定必须同基准**：`scrollToMessage` 使用 `scrollIntoView({ block: "start" })`，把目标提问对齐到视口顶边（保留 `scroll-mt-4` 的 16px 留白），因此判定基准也必须是顶边，容差必须 `>= 16`。历史上曾以“上 25% 视野焦点最近者”判定，在短回答会话里跳转后焦点落到下一条提问上，导致“点第 N 问、高亮第 N+1 问”的偏差。
- **下方提问绝不参与**：位于折叠线以下的提问永远不是当前节点，所以阅读长回答期间所属提问保持高亮，直到下一条提问真正滚过顶边。
- **零矩形节点必须跳过**：`getBoundingClientRect()` 全 0 的元素（折叠/隐藏）不构成阅读位置，`rect.height === 0` 时忽略。
- **触底优先**：`scrollHeight - scrollTop - clientHeight <= 60` 时直接取全局最新提问，保证“总高度不足一屏”的短会话也高亮最新一条。

## Alternatives considered

- **顶栏常驻大纲按钮** — 否决：顶栏空间在手机端较为紧凑（已有抽屉、项目名、状态指示、文件树、新建按钮），且无法提供当前滚动位置的直观进度反馈。
- **全屏时间轴章节树** — 否决：全屏或侧边大抽屉层级过重，阻断对话连贯性，不符合快速跳步的心智模型。
- **跳转改为对齐到 25% 视野焦点（保留原判定）** — 否决：手机端会在提问上方永久浪费 1/4 屏；且“看回答时高亮所属提问”的需求用“顶边 + 下方不参与”即可满足，无需两套基准线。
- **保留本地序号、只修正高亮换算** — 否决：刻度序号本身由全局 anchor 索引驱动，只修高亮会让窗口与高亮互相矛盾（45 问会话显示 39..45 时高亮 6），必须统一到全局序号空间。

## Consequences

- **收益**：既消灭了破坏沉浸感的常驻大药丸，又赋予了用户极致轻盈的代码编辑器缩略图/刻度尺般的高级交互质感；无论多少条消息都保持居中 7 个刻度，单手点开一秒跳步，2 秒自动退回静默；刻度高亮与屏幕上方的提问严格一一对应，长会话（历史分页加载）下也是。
- **代价**：判定依赖真实 DOM 几何（`data-msg-index` 必须落在可见用户消息上），跳转基准与 `scroll-mt-*` 留白耦合，容差必须随留白调整；纯函数 `viewportUserOrdinal` 只覆盖“给定偏移量选哪一条”这一段，页面几何仍需 E2E 兜底。
- **验证**：
  - `tests/message-anchors.test.ts` 算法单元测试：`computeVisibleTicks` 滑窗、`messageIndexForUserOrdinal` 后缀映射、新增 `firstLoadedUserOrdinal` 与 `viewportUserOrdinal`（顶边对齐、下方不参与、零矩形/NaN 忽略）；
  - `tests/e2e/timeline-ticks.spec.ts` 浏览器自动化端到端测试，覆盖刻度渲染、数量上限、高亮加粗变长、点击展开、点击跳转收起、2 秒无操作自动收拢，以及新增的“高亮刻度 = 视口顶边提问”（短回答几何下前后跳转 + 触底回锚）与“中途开始的 transcript 使用全局序号”（45 问会话只加载 6 条时高亮 45、窗口 39..45、滚到已加载区顶部高亮 40）；
  - 修复前后用同一份可复现 Playwright 用例取证：修复前跳转第 5 问后高亮 6、后缀会话触底高亮 6 且窗口 3..9；修复后分别为 5 与 45/39..45；
  - 全量 424 项单元测试 + 40 项 E2E 测试 100% 通过；
  - `npm run notes:check` 与 `npm run pack:check` 验证通过。
