# Agent Note: 右侧悬浮刻度状提问导航与节点跳转（Timeline Ticks）

Status: implemented

## Problem

在 v0.1.139 中彻底移除右下角常驻外挂式翻页胶囊后，消息区恢复了纯粹干净的对话阅读流，但用户在长对话中缺少了快速感知历史提问结构、跨节点快速跳转与回溯消息的交互入口。传统的目录或外挂药丸存在以下痛点：

1. **常驻外挂遮挡内容**：固定在右下角的大体积胶囊容易遮挡文字与滚底按钮，视觉上如同附着在网页上的外挂插件；
2. **长列表铺满屏幕**：当对话达到几十轮时，若简单按消息数量渲染一长条滚动条或垂直索引，会从头到尾铺满屏幕右侧，极其混乱；
3. **缺少瞬时概览与触后收拢机制**：用户通常只需要扫一眼当前处于第几问，并在需要时快速切换，不需要大面积弹窗长期占据视野。

## Decision

设计并落地右侧悬浮刻度状时间轴（Timeline Ticks / MessageTimelineTicks）：

1. **悬浮微型刻度条（Timeline Ticks）**：
   - 整体垂直居中悬浮于会话区域右侧边缘（`absolute right-1 sm:right-2.5 top-1/2 -translate-y-1/2`），高度紧凑（约 70px），宽度仅 20px，极度低调克制；
   - 每根刻度线对应一条用户提问（`user message`）；
   - **加粗变长指示当前位置**：当前视口所在的消息节点刻度加粗变长（宽 20px、高 3.5px、陶土橙 `bg-accent`），其他刻度轻巧纤细（宽 10px、高 2px、半透明微线），伴随滚动实时动态切换；
   - **最多显示 7 个刻度线，动态居中滑动窗口**：通过 `computeVisibleTicks` 算法，在总提问数超过 7 条时，以当前浏览的节点为中心动态滑动窗口，严格限制可见刻度恒为 7 个，确保无论多长的历史对话也绝不铺满右侧屏幕。
2. **轻触展开与 2 秒无操作自动收拢交互**：
   - 默认状态仅展示纯净细微的刻度线；
   - 第一次点击刻度条时，向左平滑滑出一个紧凑的消息卡片浮层，展示对应刻度节点的文字摘要与序号；
   - 用户可直接点击任意消息节点进行平滑滚动跳转与目标气泡闪烁高亮（`anchor-flash`）；
   - 展开态内置 2000ms 倒计时定时器：用户在面板内触摸或鼠标移动时自动顺延；若 2 秒内无任何操作，自动平滑收拢回右侧刻度条，彻底消除关闭负担。
3. **平滑跨页拉取与兜底**：
   - 结合 `chatClient.loadHistoryThroughUserMessage`，跳转至尚未加载到内存的历史消息时，显示微型 loading 并按需拉取补全后无缝滚动定位；
   - 在展开面板底部提供“全量大纲”入口，支持长达数百条会话下的全局检索。

## Alternatives considered

- **顶栏常驻大纲按钮** — 否决：顶栏空间在手机端较为紧凑（已有抽屉、项目名、状态指示、文件树、新建按钮），且无法提供当前滚动位置的直观进度反馈。
- **全屏时间轴章节树** — 否决：全屏或侧边大抽屉层级过重，阻断对话连贯性，不符合快速跳步的心智模型。

## Consequences

- **收益**：既消灭了破坏沉浸感的常驻大药丸，又赋予了用户极致轻盈的代码编辑器缩略图/刻度尺般的高级交互质感；无论多少条消息都保持居中 7 个刻度，单手点开一秒跳步，2 秒自动退回静默。
- **验证**：
  - 新增 `tests/message-anchors.test.ts` 算法单元测试；
  - 新增 `tests/e2e/timeline-ticks.spec.ts` 浏览器自动化端到端测试，全面覆盖刻度渲染、数量上限、高亮加粗变长、点击展开、点击跳转收起与 2 秒无操作自动收拢；
  - 全量 422 项单元测试 + 37 项 E2E 测试 100% 通过；
  - `npm run notes:check` 与 `npm run pack:check` 验证通过。
